# AI-UsageManager

Tracks how much of your Claude / ChatGPT / Gemini / Azure OpenAI / Anthropic API
usage you've burned through — subscription quotas and API billing in one screen,
per account.

This repository holds **the VS Code extension** (`vscode-extension/`) together
with the Python backend it bundles (`services/`, `models/`, `ui/`, `icons/` at
the repo root). The backend does all the talking to each provider; the
extension is a thin JavaScript front end that drives it over stdin/stdout.

A `.vsix` cannot reference files outside its own directory, so the build script
(`vscode-extension/build_vsix.py`) copies the backend into
`vscode-extension/backend/` and packages the copy. Those copies are not
tracked — the originals at the repo root are the only ones to edit.

> **On the desktop build.** The same backend is also bundled into a Windows
> desktop app, `AI-UsageManager.exe`, which shares
> `%LOCALAPPDATA%\AI-UsageManager\config.json` with the extension — register an
> account in one and it appears in the other. **That app's own source (its main
> window and PyInstaller spec) is not part of this repository**; only the
> backend they share lives here. This is why `services/resources.py` knows how
> to find files inside a PyInstaller bundle, and why `ui/` contains just the
> account dialog rather than a full desktop UI.

## Supported services

Derived from `services/providers/__init__.py` — this is the list actually
wired into the account picker:

| Provider | Shows | Credential |
| --- | --- | --- |
| Claude.ai | Claude Pro / Max quotas (5-hour and weekly limits) | Session cookie |
| ChatGPT | ChatGPT quotas (weekly and others) | Session cookie |
| Gemini | Gemini app quotas (current usage and the weekly limit) | Session cookie |
| Azure OpenAI | Cumulative cost (JPY) of an internal AOAI gateway, broken down by model | API key |
| Anthropic API | This month's Claude API cost (USD) broken down by model | Admin API key (`sk-ant-admin...`) |

The cookie-based providers (Claude.ai, ChatGPT, Gemini) sign in through a
separate browser window, since a VS Code Webview can't read another site's
cookies. The two API-key providers (Azure OpenAI, Anthropic API) read billing,
not quota, and don't need a browser.

Two more providers exist in the code but are currently retired from the
picker — `codex` (Codex CLI, reads a local record file) and `antigravity`
(Antigravity credit balance, blocked on a 403 from the quota endpoint). Their
implementations stay in `services/providers/` so that accounts already
configured with them still resolve correctly; see the comments in
`services/providers/__init__.py` for why.

## Repository layout

| Path | What it holds |
| --- | --- |
| `services/` | Shared backend: provider integrations, config storage and encryption, proxy handling, i18n, locale catalogs (`services/locales/`) |
| `models/` | Shared data model (`Account`) |
| `ui/` | Shared PySide6 dialog for adding/editing accounts and driving the login browser window |
| `icons/` | Shared application icon |
| `vscode-extension/` | The VS Code extension: `.js` front end (no build step, no `node_modules`), `build_vsix.py`, and localization files. `vscode-extension/backend/` is generated by the build (see `.gitignore`) and isn't tracked, except for `cli.py` and `gui_helper.py`, which are originals that live only there |
| `dist/` | Build output (git-ignored) — `.vsix` packages land here |
| `LICENSE` | MIT license text |

## Building the VS Code extension

```sh
python vscode-extension/build_vsix.py
```

This does five things, in order:

1. Copies `services/`, `models/`, `icons/`, and `ui/account_dialog.py` from
   the repo root into `vscode-extension/backend/`, replacing whatever copy
   was there before (so a module deleted from the original doesn't linger in
   the vsix).
2. Runs `node --check` on every `.js` file in the extension for a syntax pass.
3. Actually `require()`s `extension.js` in Node (with a stub `vscode` module),
   because a syntax check alone won't catch a reference to something
   undefined — that only surfaces when the module body is evaluated.
4. Validates that the translation catalogs agree with each other (see
   Localization below).
5. Runs `vsce package` and writes the `.vsix` to `dist/`.

It needs **Node.js** on `PATH` (for `node --check`, the require check, and to
run `vsce`), but no `npm install` — the extension has no `node_modules` and
requires only `vscode` and Node's own built-ins. If `vsce` isn't installed,
the script falls back to `npx @vscode/vsce` automatically.

## Localization

Four languages: English (source), Japanese, Korean, Chinese (Simplified).
Selectable via the `aiUsageManager.language` setting (`auto` / `en` / `ja` /
`ko` / `zh-cn`).

Each language lives in three separate catalog families, because the strings
come from three different runtimes:

| Catalog | Covers | English variant |
| --- | --- | --- |
| `services/locales/{ja,ko,zh-cn}.json` | Backend (Python) strings | None — English is the source text itself, no catalog file |
| `vscode-extension/l10n/bundle.l10n.{ja,ko,zh-cn}.json` | Extension host and webview JS strings | None, same reason |
| `vscode-extension/package.nls.json` + `.ja` / `.ko` / `.zh-cn` | `package.json` contribution points (command titles, settings) | `package.nls.json` is the English base |

`build_vsix.py`'s `check_l10n()` step fails the build if these catalogs
disagree — a missing language file, a key present in one language but not
another, or a `{placeholder}` that doesn't match between source and
translation. It does not check that every string in the source has been
translated (untranslated strings just fall back to English); what it catches
is a catalog that's been edited out of sync with the others.

## Credentials and privacy

- Config file: `%LOCALAPPDATA%\AI-UsageManager\config.json`. Placed under the
  user profile rather than the source folder so it isn't accidentally synced
  or shared alongside the code (see `services/config_manager.py`).
- Session cookies and API keys are encrypted before being written, using
  Windows DPAPI (`services/secret_store.py`, `CryptProtectData` /
  `CryptUnprotectData` via `ctypes` — no extra dependency). DPAPI-protected
  data only decrypts for the same Windows user on the same machine, so
  copying the config file elsewhere doesn't expose the credentials in it.
- Where DPAPI isn't available (non-Windows, or the call fails), credentials
  are stored in plaintext and the UI shows a visible warning rather than
  silently downgrading.
- In the VS Code extension, the Webview never receives the credential itself
  — only whether an account is configured. A Webview's contents can be
  inspected with DevTools, so there's no reason to put a cookie there.
- Each provider only talks to the service the credential belongs to (e.g. the
  Claude.ai cookie is only ever sent to `claude.ai`). Nothing is relayed to
  any third party.

## 日本語

Claude / ChatGPT / Gemini / Azure OpenAI / Anthropic API の**利用枠の消費率と
課金額**を1画面で確認する **VS Code 拡張** です。

このリポジトリには拡張 (`vscode-extension/`) と、拡張が同梱する Python
バックエンド (直下の `services/` `models/` `ui/` `icons/`) が入っています。
取得ロジックはすべてバックエンド側にあり、拡張の JavaScript は
標準入出力でそれを動かすだけの薄い front end です。

vsix は拡張ディレクトリの外を参照できないため、
`vscode-extension/build_vsix.py` がバックエンドを
`vscode-extension/backend/` へコピーしてから固めます。コピーは追跡して
いません — 直すのは直下にある原本の1箇所だけです。

> **デスクトップ版について。** 同じバックエンドは Windows デスクトップ版
> `AI-UsageManager.exe` にも同梱されており、設定ファイル
> (`%LOCALAPPDATA%\AI-UsageManager\config.json`) を拡張と共有します
> (片方で登録したアカウントがもう片方にも出ます)。ただし
> **その本体のソース (メイン画面や PyInstaller の spec) はこのリポジトリには
> 含まれていません。** ここにあるのは共有しているバックエンドだけです。
> `services/resources.py` が PyInstaller のバンドルを扱えるのも、`ui/` に
> アカウント編集画面しか無いのも、この事情によります。

**対応サービス** (`services/providers/__init__.py` の一覧に基づく): Claude.ai・
ChatGPT・Gemini (いずれも Cookie 認証の利用枠)、Azure OpenAI・Anthropic API
(いずれも API キー認証の課金額)。`codex` と `antigravity` は実装は残っています
が一覧には出していません (理由は同ファイルのコメントを参照)。

**拡張のビルド**:

```sh
python vscode-extension/build_vsix.py
```

原本のコピー → `.js` の構文チェック → `extension.js` を Node で実際に読み込む
検査 → 翻訳カタログ (ja/ko/zh-cn) の整合性チェック → `vsce package` の順に
実行します。Node.js は必要ですが `npm install` は不要です (`node_modules` を
持たない拡張のため)。

**多言語対応**: en (原文) / ja / ko / zh-cn。`services/locales/`、
`vscode-extension/l10n/`、`vscode-extension/package.nls*.json` の3系統に
分かれており、`build_vsix.py` は3言語の見出しが食い違っているとビルドを
失敗させます。

**資格情報とプライバシー**: Cookie・API キーは Windows DPAPI で暗号化して
保存します。DPAPI が使えない環境では平文になり、その場合は画面に警告が
出ます。どのサービスの資格情報も、そのサービス自身にしか送信しません。
