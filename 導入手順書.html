AI-UsageManager

Claude / ChatGPT / Gemini の利用枠をあと何割使えるのかと、 Anthropic API / Azure OpenAI の今月いくら使ったのかを、 VSCode の中の1つの表にまとめて出す拡張機能です。 数字はあなた自身のログイン状態と API キーで各サービスから直接取ってくるので、 推定値ではありません。

01これは何をするもの？

バラバラの画面に散っている「残りいくら使えるか」を、1つの表に集めます。

AI のサブスクを複数契約していると、「Claude の週間枠はあと何割か」「ChatGPT の5時間枠は もう空いたか」を知るのに、そのつどそれぞれのサービスを開いて確認することになります。 API のほうはさらに面倒で、いくら使ったかは請求画面を見に行かないと分かりません。

それを VSCode の中の1画面にまとめるのが AI-UsageManager です。 アカウントを登録しておけば、枠の消費率はバーで、課金額は金額で並びます。 いちばん逼迫しているアカウントは、画面下のステータスバーに出しっぱなしになるので、 画面を開かなくても気づけます。

数字は推定ではありません 利用者自身のログイン状態 (Cookie) や API キーを使って、各サービスから実際の値を取得します。 「だいたいこれくらい使ったはず」という計算をしているわけではありません。

02どんなことができるか

取得できるのは次の5つです。枠を見るものが3つ、課金額を見るものが2つ。

取得先見えるもの認証のしかた
Claude.ai Pro / Max の枠（5時間・週間・週間 Opus・週間 Sonnet） ブラウザから取った sessionKey
ChatGPT プランの枠（5時間 / 日次 / 週間）と追加クレジット ブラウザから取った Cookie
Gemini アプリの枠（現在の使用量と週間上限） Cookie の手貼りのみ（後述）
Anthropic API 今月の課金額（USD）をモデル別に Admin API キー（sk-ant-admin01-…）
Azure OpenAI ゲートウェイの累計課金額（JPY）をモデル別に ゲートウェイの API キー

課金額にも「消費率」を出せる

Anthropic API と Azure OpenAI には上限金額（予算）を設定できます。 設定すると、金額だけでなく予算に対する消費率として、 サブスクの枠のバーと並べて表示されます。使用量の管理を1つの見方に揃えるためです。

逼迫しているアカウントがステータスバーに出る

登録したアカウントのうち最も上限に近いものが、VSCode の画面下に常時表示されます。 クリックすると使用状況の画面が開きます。不要なら設定 aiUsageManager.showStatusBar で消せます。

アカウントごとに有効・無効を切り替えられる

いま更新したくないアカウントは、登録したまま更新の対象から外せます。 消してしまうと Cookie も一緒に消えて登録し直しになるので、 一時的に止めたいだけならこちらを使ってください。

読んでいるのは公開されていないエンドポイントです

「自分のプランをどれだけ使ったか」を返す API を公開している提供元はありません。 ここで使っている経路は、Web アプリ自身の通信を確認して判明したものです。 提供元は予告なくこれを変えられます。変わった場合、その取得先は 拡張が更新されるまで数字を出せなくなります。

そのとき「0%」とは表示せず、エラーとして出します。 本当は分からなくなっているのに「まだ余裕がある」と誤解させるのが、 最も避けたい壊れ方だからです。

03必要なもの

Python のパッケージが2段階に分かれています。まず上の2つだけで動きます。

必要なもの条件確認・用意のしかた
Visual Studio Code 1.85.0 以降 メニューの「ヘルプ」→「バージョン情報」
Python 3.9 以降 ターミナルで python --version が動けば大丈夫です
requests / urllib3 表示と更新に必須 pip install requests urllib3
要るのはこの2つだけです 表示・更新はもちろん、アカウントの追加・編集・削除にも他のものは要りません。 以前の版は、ログイン用のブラウザ画面のために PySide6 を求めていましたが、 その画面は無くなりました。資格情報は、利用者が普段お使いのブラウザから 取ってきて、拡張の画面に貼り付けます。

Python の探し方

設定 aiUsageManager.pythonPath が空欄なら、次の順に自動で探します。 ふつうは何も設定しなくて構いません。

  1. 設定 aiUsageManager.pythonPath
  2. Python 拡張（ms-python.python）が選んでいるインタープリタ
  3. ワークスペース直下の .venv / venv — 信頼しているフォルダのみ。信頼していないフォルダが 持ち込んだ実行ファイルを黙って動かさないためです
  4. PATH 上の py -3（Windows）/ python3

1本目に requests が無ければ、Python 拡張の答えを待って一度だけ引き直します （conda や pyenv の環境はこれで拾えます）。それでも外れる場合だけ、 aiUsageManager.pythonPath に実行ファイルのパスを入れてください。

04導入手順（vsix を入れる）

VSCode の画面だけで完結します。所要 1分ほどです。

1

拡張機能パネルを開き、「VSIX からのインストール...」を選ぶ

Ctrl+Shift+X（macOS は ⌘+Shift+X）で 拡張機能パネルを開きます。パネル右上の 「…」 メニューを押し、 いちばん下の 「VSIX からのインストール...」 を選びます。

2

受け取った vsix ファイルを選ぶ

ファイル選択のダイアログが開くので、ai-usage-manager-1.4.0.vsix を選びます。 「…が正常にインストールされました」と出たら成功です。

ファイル名が違う形で届いた場合 .vsix は中身が ZIP なので、社内のメール関門で拡張子を変えられて届くことがあります （例: .txt や .zip）。その場合は ファイル名を ai-usage-manager-1.4.0.vsix に戻してから選んでください。
3

VSCode を再読み込みする

「再読み込み」ボタンが出たら押してください。出ない場合は Ctrl+Shift+P → 「Reload Window」（開発者: ウィンドウの再読み込み）を実行します。

コマンドラインが使える環境なら、上の3ステップの代わりに code --install-extension "ai-usage-manager-1.4.0.vsix" の1行でも入ります。

05初回起動 — アイコンを押す

左端に増えた横棒グラフのアイコンを押すところから始まります。

左端のアイコンを押す → 使用状況がエディタタブで開く → 「アカウントがありません」 → 「＋ 追加」へ
サイドバーではなく、エディタタブで開きます

アイコンを押すと、サイドバーには一瞬「タブで開いています...」とだけ出て、 すぐに畳まれ、代わりにエディタタブが開きます。故障ではありません。

この画面は横に広い表なので、細いサイドバーに押し込むと 枠の名前とバーが潰れて読めなくなります。そのため、アイコンは 「タブを開くボタン」として動くようにしてあります。

ここで Python のエラーが出ることがあります

requests が入っていない Python が選ばれた場合、この時点で 「必要なパッケージが見つかりません」と出ます。

このメッセージには実際に使われた Python のパスと、そのまま貼って実行できる pip install の行が含まれています。当てずっぽうの案内ではなく、 その Python に対するコマンドなので、表示された行をそのまま実行してください。 実行後は「AI-UsageManager: バックエンドを再起動」で読み直せます。

06アカウントを登録する

画面の「＋ 追加」から登録します。取得先によって手順が3通りに分かれます。

取得先登録のしかたどこから取るか
Claude.ai
ChatGPT・Gemini も同じ		 Cookie を貼り付けます。普段お使いのブラウザで開き、開発者ツールから取り出す手順が、番号付きで画面にそのまま出ます。 既定のブラウザ
Anthropic API Admin API キーを貼り付けます。発行するページを開くボタンが画面に出ます。 既定のブラウザ
Azure OpenAI API キーを貼り付けるだけです。キーはゲートウェイの運用者から受け取ります。 —
登録は VSCode の中の1画面で完結します

追加も編集も、使用状況のタブの中に開くフォームで行います。 取得先・名前・資格情報・上限金額が一度に見え、別のウィンドウは出ません。

  1. 「＋ 追加」を押し、最初に取得先を選びます。以降の欄がその取得先に合わせて入れ替わります。
  2. 取り方の手順と、既定のブラウザでそのページを開くボタンが出ます。普段のブラウザなら、たいていは既にログイン済みです。
  3. 手順どおりにコピーして、フォームの入力欄に貼り付けます。
  4. 保存します。

丸ごと貼ってください。 Cookie を使う取得先では手順の最後が Copy as cURL になっていて、クリップボードには長いコマンドが入ります。 必要な部分だけを拡張が取り出し、残りは捨てます。 どこが Cookie かを自分で探す必要はありません。 違う行を選んでしまっても、保存すれば何が足りないかを教えます。

なぜ内蔵のブラウザをやめたか

理由は2つあります。1つは、API キーを貼るだけの人にまでブラウザエンジンの 導入を強いていたこと。もう1つは、埋め込みブラウザからのサインインを 拒む取得先があることです（Google がそうです）。それは埋め込んだ側が パスワード入力を覗けるという理由で存在する保護なので、迂回しようとするのは 筋が悪い。普段お使いのブラウザで取ってくるほうが正しく、 そちらは大抵ログイン済みでもあります。

1つだけ失われたものがあります。 Claude のセッションは、以前は その画面のプロファイルを使って裏で黙って更新していました。今後は期限切れが そのまま通知され、新しい資格情報を貼り直すことになります。 ChatGPT と Gemini は取得先の側で延長されるため、影響はありません。

Anthropic API には Admin API キーが要ります 課金額の取得に使うのは sk-ant-admin01-… で始まる組織の管理者用キーです。 個人アカウントでは発行できません。値は日次バケットで、Priority Tier の分は含まれないため、 実際の請求よりわずかに少なく出ます。
Azure OpenAI は社内ゲートウェイ向けです（Azure Cost Management ではありません）。 該当するゲートウェイが無い場合、この取得先は使えません。

08うまく動かないとき

まず「AI-UsageManager: ログを表示」を見てください。どこで止まったかが出ます。

症状対処
「Python を起動できませんでした」 設定 aiUsageManager.pythonPath に Python 実行ファイルのパスを入れてください。
「必要なパッケージが見つかりません」 メッセージにそのまま実行できる pip install の行が出ています。それを実行してから「バックエンドを再起動」してください。
「ブラウザで開く」を押してもブラウザが開かない 開くのはお使いの既定のブラウザです。既定のブラウザが設定されていない場合は開けません。その場合は、手順に書かれている URL を自分でブラウザに入力してください。
貼り付けて保存したのに「見つかりません」と出る 違う行を選んでいる可能性が高いです。手順の「Filter に入れる語」を飛ばすと、関係のない通信を選んでしまい、必要な Cookie が付いていません。手順のその段からやり直してください。
ChatGPT が「再ログイン」と言い続ける 同じ Cookie を貼り直しても直りません。ChatGPT 側でトークン更新が壊れている場合があり、そのときはブラウザでサインアウトして入り直す必要があります。1.4.0 以降はこの状態を見分けて、そう表示します。
しばらく使わずにいたら失効した 延命は取得のついでにしか走りません。ChatGPT なら約90日、それを超えて拡張を動かさなければ失効します。登録し直してください。
特定の取得先だけエラーになる 提供元がエンドポイントを変えた可能性があります。この場合 0% とは表示せずエラーを出します。拡張の更新をお待ちください。
SSL エラーが出る 社内プロキシが通信を復号している環境では、環境変数 REQUESTS_CA_BUNDLE に社内 CA 証明書を指定してください。
プロキシ経由で繋がらない 「環境変数からプロキシを取り込む」で HTTP_PROXY / HTTPS_PROXY から設定を埋め、「プロキシ接続をテスト」で確認できます。認証が要る場合はユーザーIDを設定に、パスワードはコマンドから設定してください。
画面が真っ白のまま 「バックエンドを再起動」を実行してください。それでも変わらない場合は「ログを表示」の内容を確認してください。

09資格情報の扱い

利用状況を読むには資格情報が要るので、この拡張はそれを保存します。何が起きるかをそのまま書きます。

保存場所 — プロジェクトのフォルダの外

アカウント・Cookie・API キーは、次の1ファイルに入ります。

Windows: %LOCALAPPDATA%\AI-UsageManager\config.json
それ以外: $XDG_CONFIG_HOME/AI-UsageManager/config.json（無ければ ~/.config/AI-UsageManager/config.json）

プロジェクトのフォルダの外に置いているのは、フォルダごと同期・圧縮・共有されたときに、 生きたセッション Cookie が一緒に出ていかないようにするためです。

保護のしかた — Windows では DPAPI で暗号化

Cookie と API キーは DPAPI で暗号化して書き込まれます。DPAPI で保護したデータは 「同じ Windows ユーザー・同じマシン」でしか復号できないため、 config.json をコピーされてもそのままでは使えません。

DPAPI が使えない環境では平文で保存されます 黙って弱い保存に切り替えることはせず、そのことを画面に出します。 その場合は画面の下部に ⚠ 資格情報が平文で保存されています と表示されます。

送信先はそのサービスだけ

資格情報は、そのアカウントの取得先へだけ送られます （Claude.ai の Cookie が claude.ai 以外へ出ることはありません）。 このプロジェクトが持つサーバーはありません。テレメトリも解析も送っていません。

Webview には渡していません

使用状況の表に渡しているのは「設定済みかどうか」だけです。 Webview は DevTools で中身を覗ける実行環境なので、そこへ Cookie を置く理由がありません。

資格情報の寿命

ChatGPT と Gemini は、取得に成功するたびに資格情報を延命して保存し直します （ChatGPT はセッションを約90日先へ押し出し、書き戻しは1時間おき。Gemini は10分おき）。 Claude に延命の仕組みはありません。 延命は取得が成功したあとにだけ走ります — セッションは生きている間しか延ばせないためです。

次の2点は、このアプリの側では回避できません
  • 拡張を動かしていない間は延命されません。枠（ChatGPT なら約90日）を超えて使わなければ失効します。
  • 素の accessToken を貼って登録したアカウントは延命できません。交換元の Cookie が無いため、約10日で失効します。セッション画面を貼り直せば、延命できる形（sessionToken）で保存されます。

10やめたいとき

2段階です。拡張機能を抜くだけなら1つ目だけで構いません。

  1. 拡張機能をアンインストール — 拡張機能パネルで「AI-UsageManager」を探し、 歯車アイコンから「アンインストール」。
  2. 保存された資格情報も消す（任意） — 設定ファイルごと削除してください。 
    %LOCALAPPDATA%\AI-UsageManager\config.json
    アカウントを1つずつ消したいだけなら、画面の「削除」で構いません。 削除するとそのアカウント用のログイン状態（ブラウザプロファイルを含む）も一緒に消えます。
デスクトップ版も使っている場合 config.json は Windows デスクトップ版 AI-UsageManager.exe と共有しています （片方で登録したアカウントがもう片方にも出ます）。 このファイルを消すと、デスクトップ版のアカウントも一緒に消えます。
